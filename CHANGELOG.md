# Changelog

## 1.1.2 (по результатам аудита, SERG.md)
- **CI:** починен тест B4 (BUG-001); тест скорости использует медиану (BUG-022); `npm ci` вместо `npm install` (BUG-021); Node.js 22 в Dockerfile, CI и `engines` (BUG-004).
- **Безопасность:** токены приглашений маскируются в логах, без SMTP в production текст письма не логируется (BUG-002); снабженец не ведёт собственную заявку (BUG-003, администратор — исключение); зависимости обновлены: nodemailer 10, zod 4, react-router 7 — `npm audit` без уязвимостей (BUG-008); демо-пользователи отключены по умолчанию и не создаются в production (BUG-023); пароль не длиннее 72 байт (BUG-027); лимит неудачных входов на аккаунт — 30 в час независимо от IP (BUG-029); заблокированный пользователь не принимает приглашение, блокировка гасит приглашения (BUG-012); админ не сбрасывает пароль себе (BUG-011).
- **Стабильность:** значения вне диапазона → 400 вместо 500, бюджет не округляется молча (BUG-009); корректная остановка по SIGTERM (BUG-020); `/api/health` проверяет БД, HEAD для страниц (BUG-019); `statement_timeout` для пула; CSV: нет зависания при обрыве клиента и обрыв соединения при ошибке БД (R1, R2).
- **Правила:** файлы нельзя добавлять в закрытую заявку (BUG-010); комментарий автора к заявке без ответственного уходит всем снабженцам, комментарий снабжения — автору и ответственному (BUG-025).
- **Интерфейс:** выход только по 401, при сбое сети — экран «Повторить» (BUG-005); контраст кнопок ≥ 4,5:1 (BUG-006); форма заявки на 320–360 px (BUG-007); русские сообщения валидации (BUG-013); сумма 0 (BUG-014); даты в APP_TZ (BUG-015); форма редактирования без гонки загрузки (BUG-016); дорожка статуса и таблица пользователей на узких экранах (BUG-017); порядок «событие → причина» (BUG-018); «назад» и поиск в списке (BUG-024); удалён мёртвый CSS, прототип перенесён в `docs/prototype-v1.0` (BUG-028).
- **Резервные копии:** фиксированное время, оповещение об ошибке, копирование вовне, ежемесячная проверка восстановления (BUG-026).
